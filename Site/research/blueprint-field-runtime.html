Blueprint field runtime

Which blueprint resources and fields are readable after a private world loads?

Status: Verified read surfaceEvidence: ObservedBuild: 1.0Runtime: ShroudForge

What was tested

A bounded read-only probe inspected blueprint resources after the private world loaded. It did not enumerate entities, access saves, call native functions, or attempt writes.

Observed

  • One VoxelBlueprintItemRegistryResource was readable.
  • Seven VoxelBlueprintConfig resources were readable.
  • Blueprint item collections, IDs, sizes, payloads, and compression flags were present as opaque or typed values.
  • All seven configs exposed a string debugName and present snappingConfig and snappingConfig.rules values.

Unresolved

Nested payload semantics remained opaque.

The material-pool registry was present, but candidate pools and elements paths were not exposed under those names. Persistence and editing were not tested.

Conclusion

Blueprint resources are a confirmed readable runtime surface. This does not establish a supported path for editing blueprint data, placing terrain, or persisting changes.
