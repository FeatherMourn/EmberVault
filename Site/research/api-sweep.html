Finding record · Runtime APIs

Broad API sweep

What Lua-facing API surfaces are present, and which of them are operational in the tested build?

Status: PartialEvidence: ObservedBuild: 1.0Runtime: ShroudForge

Approach

The read-only sweep checked the type of runtime namespaces and functions without calling native functions, enumerating world data, reading or writing resources, creating overrides, or accessing saves.

Surfaces present

  • Runtime root, type registry, ECS registry, and component lookup
  • Runtime function metadata and operation listing
  • Runtime services and override-scope factory
  • Game asset and content lookup
  • ShroudForge settings, logging, and export

What the test established

The Lua-facing API surface exists.

The probe could identify the exposed namespaces and callable function shapes in a loaded world.

What remained unavailable

The build-specific native backend was not operational.

The runtime reported unresolved registry/layout, no registered storage types, unavailable game-thread ownership, and an unavailable resource service.

Conclusion and next step

API presence is established, but resource reads and writes remain unavailable in this profile. The next step is to match the build-specific native backend before treating API presence as usable capability.
