Full Probe Rerun

A broad read-only pass across the available runtime and catalog surfaces to determine which systems were observable, which remained schema-only, and which were blocked by environment or initialization state.

Question

What can the current ShroudForge research environment observe consistently across inventory, player state, recipes, localization, blueprints, appearance, and related resource systems?

Approach

  1. Run the bounded probe set against the known 1.0 environment.
  2. Record resource types, returned shapes, initialization state, and explicit write status.
  3. Separate direct observations from interpretations and unresolved identity questions.
  4. Compare results with the curated catalogs and earlier focused reports.

Observed

  • 146 resource types were visible during the pass.
  • Recipe, workshop, localization, and blueprint surfaces produced useful observations.
  • Inventory and player schemas were visible, but ownership and live instance identity remained unresolved.
  • A separate appearance no-op write was accepted and restored, without proving live ownership.

What did not work

The pass did not establish a repeatable player-to-inventory identity path, entity enumeration, save access, native access, or a safe general-purpose write path. Localization export remained blocked by the unavailable EML service; that is an environment limitation, not proof that localization is impossible.

Result

The project has a broad, evidence-backed map of observable schemas and resource surfaces. Runtime capability claims must remain narrow until identity, persistence, and build-matched repeatability are demonstrated.

Evidence and provenance

Primary source: 1.0/reports/full-probe-rerun-2026-10-21.md. Related records: inventory runtime access, blueprint field runtime, localization export blocked, appearance schema, and the 1.0 metadata and registry files.

Next experiment

Repeat the pass on a known build with clean EML inputs, then focus on one identity chain at a time: player context, inventory owner, item instance, and persistence boundary.
