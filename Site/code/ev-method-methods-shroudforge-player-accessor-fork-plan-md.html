0001# ShroudForge Player Accessor Fork Plan 0002 0003Status: design and source validation only 0004 0005## Objective 0006 0007Add a supported, read-only accessor for the local player entity so mods can 0008inspect player-owned inventory, equipment, appearance, and item-instance 0009components through the normal ShroudForge runtime API. 0010 0011This is a loader extension, not a process-memory hook or protection bypass. 0012The first milestone must not write ECS data, save data, or gameplay state. 0013 0014## Evidence already present in the fork 0015 0016- The fork is MIT licensed; retain the existing copyright and license notice. 0017- `ObserveExecutionView(execution_view, true)` is called from the recurring 0018 local cursor callback. The source comments identify this as the authoritative 0019 local-player execution view. 0020- `ResolveClientEcs` and the ECS session code already validate the active owner, 0021 manager, registry, entity table, layout, and world session. 0022- `read_local_cursor_input.cpp` already scans the validated main-client ECS 0023 manager for the unique `keen::ecs::ClientPlayerInput` entity and revalidates 0024 its pointer, entity ID, generation, registry, table, and session before 0025 publishing a snapshot. 0026- Existing ECS handles are generation-checked and have an identity operation, 0027 so the accessor can reuse the established handle lifetime rules. 0028- The Lua runtime already exposes typed ECS reads and field reads, but it has no 0029 public operation that returns the locally owned player handle. 0030 0031## Proposed phase-one API 0032 0033Expose one read-only operation, named consistently with the existing runtime 0034surface, for example: 0035 0036```text 0037runtime.ecs.get_local_player() 0038 -> player_handle, metadata 0039 -> nil, reason 0040``` 0041 0042The result should contain only validated, process-local metadata: 0043 0044- generation-checked ECS entity handle; 0045- current entity ID, for diagnostics and identity checks; 0046- world-session identity or epoch; 0047- source kind, identifying the main-client local-player context; 0048- observation sequence or freshness information. 0049 0050It must not expose native pointers, layout offsets, addresses, or arbitrary 0051memory access. 0052 0053## Native implementation shape 0054 00551. Extend the existing local-input state to publish the validated entity view 0056 or its existing ECS handle after unique `ClientPlayerInput` discovery. 00572. Add a small native ABI function that returns the handle and identity 0058 metadata, using the same session and stale-handle checks as existing ECS 0059 reads. 00603. Bind that function through the existing native provider loader. 00614. Add the Lua wrapper under `runtime.ecs`, gated by `runtime.ecs.read` and an 0062 active in-game world. 00635. Reuse the existing `runtime.ecs.read`, `read_fields`, and `get_template` 0064 operations for follow-up inventory and appearance inspection. 0065 0066Do not add a second player-discovery scan. The recurring local cursor path is 0067the source already used by the fork to distinguish the local client from 0068preview or hosted authority worlds. 0069 0070## Validation gates 0071 0072The accessor must return unavailable when any gate fails: 0073 0074- no active private/local world; 0075- ECS session is not ready; 0076- local cursor observation is stale; 0077- the discovered component is absent, duplicated, or ambiguous; 0078- manager, registry, entity table, entity ID, or generation changed; 0079- the handle cannot be resolved and identity-checked in the current epoch. 0080 0081The API must never guess an entity from a type query and must never enumerate 0082all entities to find a player. 0083 0084## Tests 0085 0086### Unit tests 0087 0088- unique local `ClientPlayerInput` produces a handle; 0089- absent and duplicate input components return a reason; 0090- preview-world observations cannot replace a fresh local-player observation; 0091- manager, registry, table, session, and generation changes invalidate the 0092 published handle; 0093- stale handles fail identity validation. 0094 0095### Private-world integration test 0096 00971. Start with only the fork and a diagnostic mod enabled. 00982. Load a private world. 00993. Call the accessor after readiness and record the semantic result only. 01004. Read one harmless player-owned component or field. 01015. Reload the world and confirm the old handle is rejected. 0102 0103No write test belongs in phase one. A later write phase would require separate 0104explicit approval, expected-value checks, readback, rollback, and a private 0105world. 0106 0107## Success criteria 0108 0109The fork is ready for inventory-editor research only when a private-world run 0110returns a validated local-player handle and a typed read of a player-owned 0111component. Until then, the static item-instance schemas remain evidence, not 0112live ownership proof. 0113 0114## Longer-term fork roadmap 0115 0116Keep each capability behind its own documented contract and compatibility 0117gate. Do not combine these into one unrestricted runtime surface. 0118 01191. **Player context:** expose the validated local-player handle and session 0120 metadata. Read-only. 01212. **Ownership inspection:** report whether an entity is local-player-owned, 0122 inventory-owned, equipment-owned, or unowned. Read-only. 01233. **Inventory and equipment:** expose typed item-instance IDs, slots, 0124 definitions, durability, perks, sockets, gems, and state flags. Read-only. 01254. **Appearance:** expose character setup, scale, hair, beard, color, and 0126 cosmetic references through typed reads. Read-only first. 01275. **Lifecycle and readiness:** expose world-ready, ECS-ready, resource-ready, 0128 session-change, and stale-handle events so probes do not race startup. 01296. **Localization and resources:** expose validated language selection, 0130 localization-key lookup, and resource provenance where the current build 0131 supports them. 01327. **Diagnostics:** provide a capability report for the detected game build, 0133 including available APIs, denied APIs, profile identity, and evidence age. 01348. **Guarded private-world writes:** only after readback is proven, add narrow 0135 expected-value writes with ownership checks, rollback, save-boundary rules, 0136 and an opt-in private-world gate. No multiplayer or protection bypass. 0137 0138The fork should remain private until phases one through four pass integration 0139tests and the API documentation clearly distinguishes represented, readable, 0140 writable, and persistent behavior. 0141
