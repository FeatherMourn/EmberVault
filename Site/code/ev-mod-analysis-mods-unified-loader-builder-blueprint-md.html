0001# Unified Proxy and Multi-DLL Loader â€” Builder's Blueprint 0002 0003## Objective 0004 0005Build one management tool that combines the useful parts of ModLoader Proxy and MultiDLL Installer while preserving ShroudForge's working DLL and loader path. The tool must provide ordered native-DLL loading, backups, configuration, validation, and reliable rollback. 0006 0007The tool should also install ordinary non-DLL mods, such as Lua, EML, configuration, and asset packages, using the same staging, preview, backup, and rollback process. 0008 0009## Primary requirement: preserve ShroudForge 0010 0011ShroudForge remains the primary loader in its profile. The tool must not replace or rename ShroudForge's DLL merely to add compatible native mods. Instead, it should load approved plugin DLLs beneath the existing ShroudForge/proxy chain and make the order visible before activation. 0012 0013The tool must classify every native DLL as one of: 0014 0015- **Compatible plugin:** can be loaded by the existing chain. 0016- **Chainable proxy:** may be forwarded through a controlled proxy route after export and dependency validation. 0017- **Standalone root loader:** wants to own the game's entry point and must be isolated in a separate profile unless a verified forwarding route exists. 0018- **Unknown:** blocked until inspected. 0019 0020Non-native packages receive a separate deployment classification: 0021 0022- **Regular mod:** contains Lua, EML, configuration, or asset files and no root-loader DLL. It can be staged and copied to its declared game subfolder after path validation. 0023- **Mixed package:** contains both regular mod files and native or root-loader files. It must be split into components and reviewed before deployment. 0024 0025### Category flow 0026 0027```mermaid 0028flowchart TD 0029 A[Native DLL] --> B{Can it load under the current chain?} 0030 B -->|Yes, ordinary plugin| C[Compatible plugin\nLoad under ShroudForge] 0031 B -->|It forwards another DLL| D[Chainable proxy\nValidate exports and target] 0032 B -->|It wants the root entry point| E[Standalone root loader\nUse isolated profile] 0033 B -->|Cannot determine safely| F[Unknown\nBlock until inspected] 0034``` 0035 0036In practical terms: 0037 0038- **Compatible plugin** means the DLL is designed to be loaded by a loader and does not need to replace the game's root DLL. Creative, XHL plugins, and the M182 panel are examples in the current setup. 0039- **Chainable proxy** means the DLL is itself a forwarding layer. It may be usable, but only after checking exports, forwarding targets, and load order. 0040- **Standalone root loader** means the DLL expects to be the game's `dinput8.dll`, `winmm.dll`, or similar entry point. Shroudtopia and Stat Sliders are examples that should use isolated profiles. 0041- **Unknown** means the package lacks enough evidence. The tool should refuse to activate it automatically rather than guess. 0042 0043## Recommended scope for version one 0044 0045Version one should manage native Windows DLL mods for single-player or private testing. It should not rewrite ShroudForge or EML configuration, inject Lua, or attempt to make incompatible standalone loaders chain automatically. 0046 0047## Core design 0048 00491. **Root proxy** â€” one supported game DLL name owns the game entry point and forwards all original exports; in the ShroudForge profile, this path must preserve ShroudForge. 00502. **Manifest-based mod list** â€” each mod declares its DLL path, load order, dependencies, proxy status, and compatibility notes. 00513. **Ordered loader** â€” explicit entries load first; dependency order is validated before launch and shown in a preview. 00524. **Standalone-loader detection** â€” identify DLLs that expect to own the root entry point and require explicit confirmation or isolation. 00535. **Backup manager** â€” create a timestamped backup of every root DLL and configuration file before changes, including the untouched ShroudForge files. 00546. **Health check** â€” validate PE architecture, required exports, file presence, duplicate entries, and target paths before installation. 00557. **Recovery mode** â€” restore the last known-good backup if launch fails or the user selects rollback. 00568. **Logging** â€” record the selected profile, load order, forwarded target, DLL failures, and rollback actions. 00579. **Regular package deployment** â€” copy validated non-DLL files into their declared destination, reject path traversal, and preserve the package's folder structure. 0058 0059## Profiles 0060 0061Use separate profiles instead of stacking incompatible loaders: 0062 0063- **ShroudForge profile:** current working proxy plus ShroudForge forwarding and approved native plugins. ShroudForge remains present and is never silently replaced. 0064- **Standalone-loader profile:** an isolated profile for Shroudtopia, Stat Sliders, or another root-owning loader. 0065- **Clean profile:** no mod proxy, used to verify the unmodified game. 0066 0067Only one profile should be active at a time. 0068 0069## Installation flow 0070 0071```mermaid 0072flowchart TD 0073 A[Research library] --> B[Scan package] 0074 B --> C{Package type} 0075 C -->|Regular Lua/EML/assets| D[Validate destination paths] 0076 C -->|Compatible native plugin| E[Validate architecture, exports, and order] 0077 C -->|Root loader or mixed package| F[Quarantine for review] 0078 D --> G[Stage files] 0079 E --> G 0080 F --> H[Require separate profile or manual decision] 0081 G --> I[Show install preview] 0082 I --> J[Back up active game files] 0083 J --> K[Deploy selected profile] 0084 K --> L[Write logs and transaction record] 0085 L --> M{Launch succeeds?} 0086 M -->|Yes| N[Keep profile active] 0087 M -->|No| O[Restore previous backup] 0088``` 0089 0090In plain language: 0091 00921. The tool treats the research folder as a library and never installs directly from an archive. 00932. It scans the package and classifies regular files, compatible plugins, root loaders, and mixed content. 00943. It stages only the selected files in a temporary profile. 00954. It validates destinations, architecture, exports, dependencies, and load order. 00965. It shows exactly what will be copied, replaced, or left untouched. 00976. After confirmation, it backs up the active game files and deploys the profile. 00987. It records the transaction and loader output. 00998. If launch validation fails, it restores the previous profile. 0100 0101## Detailed architecture walkthrough 0102 0103### 1.
