0001# SF Survival â€” `sf-survival` 0002 0003## Short summary 0004 0005SF Survival is a ShroudForge runtime mod built around the public typed ECS, template, and engine-service APIs. It changes survival values such as stamina, mana, oxygen, body heat, regeneration, fall damage, and weapon durability while preserving restoration behavior when settings are disabled. 0006 0007## How it works 0008 0009The extended manifest defines eight settings and places them in one Survival group. The Lua entry point creates a shared override manager, waits for an authoritative world, queries player entities, reads original values, and applies typed changes through runtime helper APIs. It runs every 100 milliseconds so it can bind to players, notice changed maxima, retry busy engine gates, and restore settings that were turned off. 0010 0011The mod does not use hard-coded process addresses or native DLL bindings. Its design relies on ShroudForge admitting typed read/write operations and on the runtime tracking ownership of each changed value. 0012 0013## Implemented mappings 0014 0015- Infinite stamina: sets `Stamina_Min` equal to the original `Stamina_Max`. 0016- Infinite mana: sets `Mana_Min` equal to `Mana_Max`. 0017- Infinite underwater breath: sets `Oxygen_Min` equal to `Oxygen_Max`. 0018- Infinite frost timer: sets `BodyHeat_Min` equal to `BodyHeat_Max`. 0019- Fast health and mana regeneration: multiplies existing recharge by 100, capped at 65536; it does not create regeneration if the original rate is zero. 0020- No fall damage: raises the player template's fall-damage start distance to at least the lethal distance. 0021- Infinite weapon durability: changes the hosted world's `ecs::GameSettings.enableDurability` service field. 0022 0023## Safety and restoration design 0024 0025The mod records the value it owned before changing it and compares the current value before restoration. An external change is preserved rather than overwritten. If the engine is busy, the mod retries. If the result is uncertain or the world session is invalidated, it stops mutating and reports that a restart may be required. 0026 0027The storage scopes matter: attributes are per authoritative player entity, fall damage is shared by entities using a template, and durability affects the locally hosted world and carried items. 0028 0029## Runtime evidence 0030 0031ShroudForge logs showed SF Survival loading and transitioning between waiting and resolved states as world/runtime access became available. The logs also showed that no live player entity was available during some phases, which is an expected state while at menus or before a world is ready. 0032 0033## Reverse-engineering assessment 0034 0035This is a strong reference implementation for safe ShroudForge Lua mods. Its main patterns are: typed target factories, explicit ownership, reversible writes, authoritative-world checks, bounded update loops, and status reporting. Those patterns are directly reusable for future mods such as autorun or a spellbook, provided the required runtime targets exist. 0036 0037## Confidence 0038 0039- Manifest and source behavior: high; directly inspected. 0040- Runtime API strategy: high; directly shown in source and README. 0041- Actual gameplay result for every setting: medium; requires an offline world test on the matching build. 0042 0043
