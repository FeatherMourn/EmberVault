0001# SF Crafting Essentials â€” `sf-crafting-essentials` 0002 0003## Short summary 0004 0005SF Crafting Essentials combines pregame recipe preparation with live runtime changes. It can remove recipe ingredients and water charges before startup, keep supported used items from being consumed, and alter production times while preserving relative recipe durations. 0006 0007## How it works 0008 0009The mod has two phases. During the `pregame` phase it scans `keen::RecipeRegistryResource`, edits recipe input counts and water charges when the no-cost option is enabled, and optionally prepares one shared duration for timed recipes. During the `ingame` phase it uses typed resource writes and an override manager to adjust loaded recipe durations and supported action-sequence consume flags. 0010 0011The source processes resources incrementally with budgets rather than scanning everything in one update. It caches resource identities, reacquires resources by GUID/type/part, validates each target path, and reports pending scans or unavailable write scopes through ShroudForge status reporting. 0012 0013## Settings 0014 0015- No Recipe Resource Costs: removes direct ingredients, category inputs, and water charges before startup; it does not change building or upgrade costs. 0016- No Item Consumption: changes supported item-use actions to retain the item; unsupported actions remain unchanged. 0017- Recipe Time Mode: keeps original live scaling or uses a fixed shared duration prepared at startup. 0018- Production Time in Seconds: fixed base duration for timed recipes. 0019- Production Duration Scale: live percentage scaling of loaded recipe durations, including running production. 0020 0021## Safety and limitations 0022 0023Pregame asset edits require the pregame patch capability and a restart. Live changes require an authoritative world and guarded resource-write access. The mod validates positive finite durations, limits setting ranges, and restores values when settings are disabled or the mod unloads. 0024 0025## Reverse-engineering assessment 0026 0027This is a strong example of a split-phase mod: immutable or startup-sensitive data is changed before the game consumes it, while live-safe values are handled through guarded runtime resource writes. Its incremental scanning and ownership tracking are reusable patterns for future mods that need to inspect many game resources. 0028 0029## Confidence 0030 0031- Manifest, settings, and source flow: high; directly inspected. 0032- Exact game-side effect of every recipe/action path: medium; depends on the current build's resource layout and runtime write availability. 0033 0034
